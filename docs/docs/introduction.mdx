# Skittles

**Write smart contracts in TypeScript.**

<img
  src="https://skittles.dev/banner.png"
  alt="Skittles"
  style={{ width: "100%", borderRadius: "12px", marginBottom: "2rem" }}
/>

Skittles is an open-source compiler that lets you write EVM smart contracts as TypeScript classes and generates Solidity source code. You write standard TypeScript classes and types, and Skittles turns them into Solidity that Hardhat or solc compiles to ABI and bytecode.

## What is a Smart Contract?

A **smart contract** is a program that runs on a blockchain such as Ethereum. Once deployed, it can hold funds, enforce rules and execute automatically without a middleman.

Think of it like a vending machine:
- You send cryptocurrency to the contract.
- The contract follows its programmed rules.
- You receive the outcome defined by those rules, such as tokens or an NFT.
- Everything runs automatically and transparently on the blockchain.

Smart contracts are used to build decentralised applications (dApps) such as token systems, NFT marketplaces and DeFi protocols.

```typescript title="contracts/Token.ts"
import { address, msg, SkittlesEvent, Indexed } from "skittles";

export class Token {
  Transfer: SkittlesEvent<{
    from: Indexed<address>;
    to: Indexed<address>;
    value: number;
  }>;

  name: string = "My Token";
  symbol: string = "TKN";
  totalSupply: number = 0;
  balances: Record<address, number> = {};

  constructor(initialSupply: number) {
    this.totalSupply = initialSupply;
    this.balances[msg.sender] = initialSupply;
  }

  transfer(to: address, amount: number): boolean {
    if (this.balances[msg.sender] < amount) {
      throw new Error("Insufficient balance");
    }
    this.balances[msg.sender] -= amount;
    this.balances[to] += amount;
    this.Transfer.emit({ from: msg.sender, to, value: amount });
    return true;
  }
}
```

This contract defines a simple token with balances and transfers. The `balances` record tracks how many tokens each address owns. The `transfer` method lets users send tokens to another address after checking that the caller has enough balance. The `Transfer` event logs each transfer on the blockchain so external tools can track activity.

## Why Skittles?

**You write TypeScript.** Define contracts as exported TypeScript classes using familiar types and syntax, instead of writing Solidity syntax and memory keywords by hand.

**Your editor already supports it.** Autocomplete, type checking, go-to-definition and refactoring work out of the box because your contracts are regular TypeScript files.

**Skittles handles Solidity translation.** It maps TypeScript types to Solidity types, sets visibility rules (mapping `private` and protected members to Solidity internal visibility so child contracts can use them) and infers state mutability from what each function reads or writes.

**You test with familiar tools.** Scaffolded projects use Hardhat 3 with Mocha, Chai matchers and ethers v6 against Hardhat's local simulated network.

## Features

- **Familiar types**: Use `number` for amounts and counters, `string` for text, `boolean` for flags, `address` for wallet addresses, `bytes` for raw data, `Record<K,V>` or `Map<K,V>` for key-value storage, arrays, type aliases for custom structures, interfaces and enums.
- **Class properties**: Properties become persistent state variables. Use `public`, `private`, `readonly` and `static readonly` as in TypeScript.
- **Methods**: Mutability is inferred automatically from whether a function uses `msg.value`, writes state, reads state or EVM globals, or does none of those. Supports `virtual` and `override` for inheritance, getters and setters, plus `receive()` and `fallback()` for handling payments and calls.
- **Events**: Log activity on the blockchain with `SkittlesEvent<T>` and mark searchable parameters with `Indexed<T>`.
- **Custom errors**: Define typed errors using `SkittlesError<T>` or by extending the `Error` class.
- **Inheritance**: Share behaviour across contracts with `extends` and `super`.
- **Control flow**: Standard JavaScript patterns work, including `if`/`else`, `for`, `while`, `do`/`while`, `for...of`, `for...in` (enums), `switch`/`case`, ternary operators and `try`/`catch` for external calls.
- **Destructuring**: Array, tuple and object destructuring for local variables and function return values.
- **[Operators](/guide/operators)**: Arithmetic (`+`, `-`, `*`, `/`, `%`, `**`), comparison, logical, bitwise and compound assignment operators work as expected.
- **Blockchain globals**: Access `msg.sender` (who called the function), `msg.value` (how much they sent), `block.timestamp`, `block.number`, `tx.origin` and other EVM globals.
- **Built-in functions**: `keccak256()`, `sha256()`, `ecrecover()`, `abi.encode()` and `abi.encodePacked()` for cryptography and data encoding, plus `Math.min()`, `Math.max()`, `Math.sqrt()` and `Math.pow()` for common maths operations.
- **Standard library**: Built-in ERC20, ERC20Permit, ERC20Votes (tracks current votes only), ERC721, Ownable, AccessControl, Pausable and ReentrancyGuard contracts based on OpenZeppelin Contracts v5, ready to extend with no extra packages needed.
- **Debugging**: `console.log()` maps to Hardhat's console and is removed from the generated Solidity when the consoleLog config option is false (the default; scaffolded projects set it to true).
- **Multi-file projects**: Share types, constants and functions across contract files.
- **Incremental builds**: SHA-256 file hashing serves unchanged files from the cache and recompiles files that depend on changed shared types, constants or functions.

## Build Output

When you compile your TypeScript contracts, Skittles writes the generated Solidity to artifacts/solidity/:

```
artifacts/
  solidity/     # Generated contract source code
```

Run npx skittles compile to compile your contracts, then use Hardhat to test and deploy them. In a scaffolded project, npm run test compiles your contracts and runs the tests. The generated ABI and bytecode work with EVM tools such as ethers.js, viem, Hardhat and Foundry, and can be deployed to EVM chains such as Ethereum, Polygon, Arbitrum and Base.

## Under the Hood

<details>
<summary>How does Skittles work? (Click to expand)</summary>

Under the hood, Skittles compiles your TypeScript into Solidity source code:

- **Reviewable**: Security reviewers can read and inspect the generated Solidity directly.
- **Verifiable**: You can verify your contracts on Etherscan and other block explorers.
- **Compatible**: The output works with EVM tools such as ethers.js, viem, Hardhat and Foundry.
- **Transparent**: The generated Solidity is human-readable and written to artifacts/solidity/.

Compilation happens in three stages:
1. Parse your TypeScript with the official TypeScript compiler.
2. Build an intermediate representation and analyse it for types, visibility and mutability.
3. Generate Solidity source files.

See the [Under the Hood](/guide/under-the-hood) guide for more detail on how the compiler works.

</details>
