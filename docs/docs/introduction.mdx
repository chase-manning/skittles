# Skittles

Skittles is an open-source compiler that turns TypeScript classes into Solidity for EVM smart contracts.

<img
  src="https://skittles.dev/banner.png"
  alt="Skittles"
  style={{ width: "100%", borderRadius: "12px", marginBottom: "2rem" }}
/>

You write exported TypeScript classes using standard TypeScript syntax and types. Skittles compiles them to Solidity source files, which Hardhat or solc then compiles to ABI and bytecode.

## What is a Smart Contract?

A smart contract is a program that runs on an EVM blockchain such as Ethereum, Polygon, Arbitrum or Base. Once deployed, it can hold funds, enforce rules and run automatically without an intermediary.

It works a bit like a vending machine:

- You send cryptocurrency or a transaction to the contract
- The contract runs its programmed rules
- You get the programmed outcome, such as tokens or an NFT
- The code runs on the blockchain without a middleman

Smart contracts are used for decentralised applications (dApps) such as tokens, NFT marketplaces and DeFi protocols.

```typescript title="contracts/Token.ts"
import { address, msg, SkittlesEvent, Indexed } from "skittles";

export class Token {
  Transfer: SkittlesEvent<{
    from: Indexed<address>;
    to: Indexed<address>;
    value: number;
  }>;

  name: string = "My Token";
  symbol: string = "TKN";
  totalSupply: number = 0;
  balances: Record<address, number> = {};

  constructor(initialSupply: number) {
    this.totalSupply = initialSupply;
    this.balances[msg.sender] = initialSupply;
  }

  transfer(to: address, amount: number): boolean {
    if (this.balances[msg.sender] < amount) {
      throw new Error("Insufficient balance");
    }
    this.balances[msg.sender] -= amount;
    this.balances[to] += amount;
    this.Transfer.emit({ from: msg.sender, to, value: amount });
    return true;
  }
}
```

This contract defines a basic token with balances and transfers. The `balances` record tracks how many tokens each address holds. The `transfer` method checks that the sender has enough balance, updates both balances and emits a `Transfer` event so off-chain tools can track transfers on the blockchain.

## Why Skittles?

**Write in TypeScript.** Contracts are standard TypeScript classes, so you don't have to learn Solidity syntax or memory keywords before writing a contract.

**Editor support.** Autocomplete, editor type checking, go-to-definition and refactoring work in your TypeScript editor as they do for any other TypeScript code.

**Solidity details handled by the compiler.** Skittles converts TypeScript types to Solidity types, maps visibility rules and infers function mutability from your code.

**Standard JavaScript testing tools.** Scaffolded projects test contracts with Hardhat, Mocha, Chai and ethers v6 against Hardhat's local simulated network.

## Features

- **Familiar types**: Use `number` for amounts and counters, `string` for text, `boolean` for flags, `address` for wallet addresses, `bytes` for raw data, `Record<K,V>` or `Map<K,V>` for key-value storage, arrays, type aliases for custom structures, interfaces and enums
- **Class properties**: Class properties become persistent state variables, with `public`, `private`, `protected`, `readonly` and `static readonly`. Both `private` and `protected` compile to Solidity `internal`; use `protected` for members that child contracts need, because TypeScript does not allow a subclass to access `private` members
- **Methods**: Function mutability (`payable`, `nonpayable`, `view` or `pure`) is inferred from what a method reads or writes, with no annotations needed. Supports `virtual`/`override` for inheritance, getters and setters, and `receive()` and `fallback()` for handling payments
- **Events**: Log on-chain activity with `SkittlesEvent<T>` and mark searchable parameters with `Indexed<T>`
- **Custom errors**: Define typed errors with `SkittlesError<T>` or by extending `Error`
- **Inheritance**: Extend base contracts with `extends` and `super`
- **Control flow**: Supports `if`/`else`, `for`, `while`, `do`/`while`, `for...of`, `for...in` (for enums), `switch`/`case`, ternary operators and `try`/`catch` for external calls
- **Destructuring**: Array, tuple and object destructuring for local variables and function return values
- **[Operators](/guide/operators)**: Arithmetic (`+`, `-`, `*`, `/`, `%`, `**`), comparison, logical, bitwise and compound assignment operators
- **Blockchain globals**: Access `msg.sender` (the caller), `msg.value` (the value sent), `block.timestamp`, `block.number` and `tx.origin`
- **Built-in functions**: `keccak256()`, `sha256()`, `ecrecover()`, `abi.encode()` and `abi.encodePacked()` for hashing and encoding, plus `Math.min()`, `Math.max()`, `Math.sqrt()` and `Math.pow()` for maths
- **Standard library**: Import ERC20, ERC20Permit, ERC20Votes (tracks current votes only), ERC721, Ownable, AccessControl, Pausable and ReentrancyGuard from `skittles/contracts`. These are Skittles' own TypeScript implementations based on OpenZeppelin Contracts v5
- **Debugging**: `console.log()` maps to Hardhat's console and is removed from the generated Solidity when the `consoleLog` option in `skittles.config.json` is false (the default)
- **Multi-file projects**: Share types, enums, interfaces, constants and functions across contract files
- **Incremental builds**: Each file is hashed with SHA-256 and unchanged files are served from the cache. Changing a shared definition recompiles every file, and changing a parent contract recompiles files that extend it

## Build Output

Compiling your TypeScript contracts writes the generated Solidity to `artifacts/solidity/`:

```
artifacts/
  solidity/     # Generated contract source code
```

Run `npx skittles compile` to compile your contracts, then use Hardhat to test and deploy them. In a project created with `npx skittles@latest init`, `npm run test` compiles your contracts and runs the Hardhat test suite. The generated Solidity, ABI and bytecode work with tools such as ethers.js, viem, Hardhat and Foundry.

## Under the Hood

<details>
<summary>How does Skittles work? (Click to expand)</summary>

Skittles compiles TypeScript to standard Solidity source code:

- **Readable**: The generated Solidity is written to `artifacts/solidity/` so you and security reviewers can inspect it directly
- **Verifiable**: You can submit the generated Solidity for verification on block explorers such as Etherscan
- **Compatible**: The compiled ABI and bytecode work with tools such as ethers.js, viem, Hardhat and Foundry, and can be deployed to EVM chains such as Ethereum, Polygon, Arbitrum and Base

Compilation runs in three stages:

1. Parse your TypeScript with the official TypeScript compiler
2. Build an intermediate representation and analyse it (types, visibility and mutability)
3. Generate Solidity source files

For more detail on each stage, read the [Under the Hood](/guide/under-the-hood) guide.

</details>
